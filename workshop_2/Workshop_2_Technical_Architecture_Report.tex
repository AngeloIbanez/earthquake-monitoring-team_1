\begin{abstract}
Operational natural hazard monitoring requires fault-tolerant, automated data engineering pipelines capable of ingesting heterogeneous telemetry and transforming raw payloads into analysis-ready datasets without manual intervention. Building upon the source characterization and canonical data contract established in Workshop~\#1, this paper presents the complete technical architecture and containerized implementation of the Bronze and Silver layers for the Team~1 Earthquake Activity Monitoring System. We deploy a multi-container infrastructure using Docker Compose integrating Apache Airflow~2.10.4 and PostgreSQL~16. Using Airflow's modern TaskFlow API (\texttt{@dag} and \texttt{@task}) alongside a \texttt{FileSensor} operator, we implement two automated Directed Acyclic Graphs (DAGs): \texttt{bronze\_ingestion\_dag}, which extracts seismic event streams from the USGS FDSN API into immutable timestamped JSON files in \texttt{datalake\_bronze/}, and \texttt{silver\_processing\_dag}, which detects new arrivals, enforces physical and statistical validation gates, normalizes text and UTC timestamps, computes radiated seismic energy ($E = 10^{4.8 + 1.5M}$), and persists deduplicated outputs simultaneously to compressed Apache Parquet files in \texttt{datalake\_silver/} and an ACID-compliant PostgreSQL table (\texttt{earthquakes\_curated}). Empirical verification across nine Bronze runs and eight Silver runs demonstrates $100\%$ schema compliance, $0.0\%$ missing values across 245 unique curated earthquakes, an $82.4\%$ storage footprint reduction via Snappy-compressed Parquet, and complete root-cause resolution of an initial XCom \texttt{pd.Timestamp} JSON serialization fault.
\end{abstract}

\section{Introduction and Executive Summary}
\noindent\textbf{GitHub Repository:} \url{https://github.com/AngeloIbanez/earthquake-monitoring-team_1} (Branch: \texttt{workshop\_2})\\[0.15cm]
In Workshop~\#1, Team~1 formalized the geophysical domain of earthquake activity monitoring, validated four open seismological data sources---United States Geological Survey (USGS) FDSN Event Web Service~\cite{usgs_fdsn}, Euro-Mediterranean Seismological Centre (EMSC) FDSN Portal~\cite{emsc_fdsn}, USGS Real-Time GeoJSON Feeds~\cite{usgs_rt}, and GDACS RSS~2.0 Alerts~\cite{gdacs}---and uncovered five concrete data-quality anomalies across raw telemetry payloads. Translating that conceptual data contract into a production-ready engineering system requires automated orchestration, isolated containerization, deterministic data preprocessing, and immutable lineage tracking.

This report documents the design, deployment, and verification of Workshop~\#2. Our engineering approach adopts the industry-standard \textbf{Medallion Data Lakehouse Architecture}~\cite{armbrust2021lakehouse}, decoupling raw data landing (\textbf{Bronze}), validated and deduplicated tabular curation (\textbf{Silver}), and downstream analytical aggregations (\textbf{Gold}). The entire software stack is containerized via Docker Compose~\cite{docker_docs}, orchestrating Apache Airflow~2.10.4~\cite{airflow_docs} backed by PostgreSQL~16~\cite{postgres_docs}. By combining columnar Apache Parquet persistence~\cite{parquet_docs} in \texttt{datalake\_silver/} with relational idempotent upserts in PostgreSQL (\texttt{earthquakes\_curated}), the architecture satisfies both distributed batch analytics (planned for PySpark in Workshop~\#3) and low-latency operational querying (planned for the Plotly Dash monitoring interface in Workshop~\#4).

\subsection{Justification of Technology Choices}
\begin{enumerate}
    \item \textbf{Apache Airflow 2.10.4 with TaskFlow API:} Airflow provides native Pythonic workflow-as-code orchestration, deterministic execution intervals (\texttt{data\_interval\_start}), automatic retry policies with backoff, and sensor operators (\texttt{FileSensor}). Using the modern \texttt{@dag} and \texttt{@task} decorators eliminates verbose operator boilerplate and manages inter-task data passing via XComs.
    \item \textbf{Pandas and Polars for Silver Preprocessing:} Seismic telemetry arrives as deeply nested hierarchical JSON (\texttt{features[].properties} and \texttt{features[].geometry.coordinates}). Flattening these structures into Pandas/Polars DataFrames enables vectorized C/Rust-backed operations for type coercion, regular-expression string cleaning, vectorized logarithmic energy computation, and hash-based deduplication in milliseconds.
    \item \textbf{Apache Parquet (PyArrow) for Silver Persistence:} Unlike CSV or JSON, which are row-oriented, untyped, and verbose, Apache Parquet is a binary columnar format with embedded schema metadata and Snappy compression~\cite{parquet_docs}. In our empirical runs, a $140.7\text{ KB}$ raw Bronze JSON payload compresses to a $24.81\text{ KB}$ Silver Parquet file---an \textbf{$82.4\%$ storage reduction}---while preserving exact \texttt{datetime64[ns, UTC]} and \texttt{float64} types required for zero-copy folder reads (\texttt{spark.read.parquet("datalake\_silver/")}) in Workshop~\#3.
    \item \textbf{PostgreSQL 16 for Metadata and Curated Storage:} PostgreSQL serves a dual role via isolated databases in a single container: managing Airflow's internal state (\texttt{airflow} DB) and storing the canonical curated earthquake table (\texttt{earthquakes\_ud} DB), supporting atomic \texttt{ON CONFLICT (event\_id) DO UPDATE} upserts.
\end{enumerate}

\subsection{File Nomenclature and Lineage Conventions}
To guarantee chronological ordering, prevent filename collisions across runs, and maintain strict data lineage between layers, the pipeline enforces deterministic UTC timestamp nomenclature:
\begin{itemize}
    \item \textbf{Bronze Layer Convention:}
    \begin{center}
    \texttt{\{source\}\_\{YYYYMMDD\}\_\{HHMMSS\}.json}\\
    \textit{Example:} \texttt{earthquakes\_20261117\_011500.json}
    \end{center}
    \item \textbf{Silver Layer Convention:}
    \begin{center}
    \texttt{\{topic\}\_silver\_\{YYYYMMDD\}\_\{HHMMSS\}.parquet}\\
    \textit{Example:} \texttt{earthquakes\_silver\_20261117\_013549.parquet}
    \end{center}
\end{itemize}
Furthermore, every row persisted in a Silver Parquet file and in PostgreSQL carries an explicit \texttt{source\_file} column recording the exact Bronze JSON filename from which it was extracted, ensuring $100\%$ backward traceability.

\section{Preprocessing Pipeline Design}
Every preprocessing rule implemented in \texttt{silver\_processing\_dag.py} is directly grounded in the empirical data-quality findings documented during Workshop~\#1 profiling.

\subsection{Null and Missing Value Handling Strategy}

Records missing primary keys (\texttt{event\_id}), origin timestamps (\texttt{raw\_time}), coordinates (\texttt{latitude}, \texttt{longitude}), or severity (\texttt{magnitude}) are dropped via \texttt{df.dropna()}, as an unlocated or unmeasured earthquake cannot be placed on a hazard map or included in energy calculations. \subsection{Text Preprocessing and Normalization}
In Workshop~\#1 (Data Quality Issue~\#3 and Issue~\#4), we observed inconsistent capitalization in magnitude scales (e.g., \texttt{ML} vs. \texttt{ml}, \texttt{Mww} vs. \texttt{mww}) and trailing whitespace or formatting noise in geographic \texttt{place} strings (e.g., \texttt{"38 km WNW of Anchor Point, Alaska"}). Our text cleaning pipeline applies:
\begin{enumerate}
    \item \textbf{Null Replacement and String Coercion:} \texttt{.fillna("Unknown Location").astype(str)}.
    \item \textbf{Whitespace Stripping:} Removal of leading/trailing spaces and line breaks via \texttt{.str.strip()}.
    \item \textbf{Case Standardization:} Lowercasing of categorical scale identifiers (\texttt{mag\_type.str.lower().str.strip()}) into \texttt{magnitude\_type} to prevent fragmented group-by aggregations in the Gold layer.
\end{enumerate}

\subsection{Outlier Detection and Physical Boundary Handling}
Outlier handling in geophysical telemetry requires distinguishing between \textbf{corrupt sensor/transmission artifacts} and \textbf{genuine extreme natural hazards}:
\begin{enumerate}
    \item \textbf{Hard Physical Boundary Gates (Filter/Drop):} The pipeline enforces geodetic and physical limits:
    \begin{align}
        -90.0^\circ \le \text{latitude} &\le +90.0^\circ, \\
        -180.0^\circ \le \text{longitude} &\le +180.0^\circ, \\
        -2.0 \le \text{magnitude} &\le 10.0.
    \end{align}
    Note that negative magnitudes down to $-2.0$ and slight negative depths (e.g., $\min(\text{depth\_km}) = -0.690\text{ km}$ observed in our Silver batch) are physically valid: they correspond to micro-earthquakes or shallow geothermal/volcanic events located in mountain edifices above the WGS84 reference geoid (sea level), as proven in Workshop~\#1 Issue~\#2.
    \item \textbf{Statistical Outlier Analysis (IQR and Z-Score Flagging):} For our curated Silver dataset ($N = 245$ events), the magnitude distribution yields $\mu = 2.453$, $\sigma = 1.034$, $Q_1 = 1.790$, median $Q_2 = 2.020$, and $Q_3 = 2.700$ ($\text{IQR} = 0.910$). Under Tukey's interquartile fence ($Q_3 + 1.5\times\text{IQR} = 4.065$) or a $Z > 3.0$ threshold ($M > 5.555$), major earthquakes such as \texttt{us7000tymu} ($M = 6.6$ in Tual, Indonesia, $Z = +4.01$) are statistical outliers because earthquake magnitudes follow a heavy-tailed exponential Gutenberg-Richter distribution~\cite{gutenberg1956}. Deleting $M \ge 5.5$ events as ``outliers'' would destroy the exact high-priority hazard signals the system is built to monitor! Consequently, hard physical violations are dropped, while statistical extremes ($Z > 3.0$) are preserved and quantified via radiated seismic energy:
    \begin{equation}
        E = 10^{4.8 + 1.5 M}\quad [\text{Joules}].
    \end{equation}
\end{enumerate}

\subsection{Cross-Batch Deduplication}
Because Bronze ingestion polls overlapping rolling windows to capture post-facto seismological revisions (proven in Workshop~\#1's two-poll experiment), the same \texttt{event\_id} appears across multiple Bronze JSON files. Within \texttt{silver\_processing\_dag}, records are sorted chronologically by Bronze file timestamp and deduplicated via \texttt{df.drop\_duplicates(subset=["event\_id"], keep="last")}. For instance, out of $362$ raw records extracted across the Bronze files, $117$ overlapping records were deduplicated, yielding $245$ unique curated earthquakes. In PostgreSQL, idempotency across runs is enforced via \texttt{ON CONFLICT (event\_id) DO UPDATE}.

\section{Docker Compose Stack Setup}
The containerized infrastructure is defined in \texttt{docker-compose.yml} and initialized via \texttt{init-db/01-create-etl-database.sql} and \texttt{.env} (\texttt{AIRFLOW\_UID=50000}).

    - ./airflow/dags:/opt/airflow/dags

\begin{itemize}
    \item \textbf{\texttt{postgres} (PostgreSQL 16):} Exposes host port \texttt{5440:5432} to avoid conflicts with local PostgreSQL installations. Mounts \texttt{./init-db:/docker-entrypoint-initdb.d} to automatically create the dedicated ETL user \texttt{etl\_ud} and database \texttt{earthquakes\_ud}, isolating business data from Airflow metadata.
    \item \textbf{\texttt{airflow-init}:} One-shot initialization container that executes \texttt{airflow db migrate} and provisions the default administrator account (\texttt{airflow} / \texttt{airflow}).
    \item \textbf{\texttt{airflow-webserver} \& \texttt{airflow-scheduler}:} Dependent on \texttt{airflow-init} completing successfully (\texttt{service\_completed\_successfully}). The webserver exposes the UI at \texttt{http://localhost:8080}, while the scheduler executes tasks locally via \texttt{LocalExecutor}.
\end{itemize}

\section{Bronze and Silver DAG Implementation}

\subsection{Bronze Ingestion DAG (\texttt{bronze\_ingestion\_dag.py})}
Implemented with the TaskFlow API (\texttt{@dag}, \texttt{@task}) on a 15-minute schedule (\texttt{*/15 * * * *}), the Bronze pipeline comprises three sequential tasks:
\begin{enumerate}
    \item \textbf{\texttt{extract\_raw\_earthquakes}:} Queries \url{https://earthquake.usgs.gov/fdsnws/event/1/query} with \texttt{format=geojson} and \texttt{minmagnitude=1.5}. Supports both scheduled execution intervals and custom manual configuration windows (\texttt{dag\_run.conf}).
    \item \textbf{\texttt{validate\_bronze\_payload}:} Verifies that the HTTP 200 payload is a valid dictionary with \texttt{type == "FeatureCollection"} and a list of \texttt{features}.
    \item \textbf{\texttt{persist\_to\_bronze}:} Writes the unmodified JSON payload to \texttt{/opt/airflow/datalake\_bronze/}\allowbreak\texttt{earthquakes\_YYYYMMDD\_HHMMSS.json}.
\end{enumerate}

\subsection{Silver Processing DAG (\texttt{silver\_processing\_dag.py})}
Scheduled every 20 minutes (\texttt{*/20 * * * *}), the Silver pipeline integrates a \texttt{FileSensor} with four TaskFlow tasks:
\begin{enumerate}
    \item \textbf{\texttt{wait\_for\_bronze\_files} (\texttt{FileSensor}):} Monitors \texttt{datalake\_bronze/earthquakes\_*.json} via \texttt{fs\_conn\_id="fs\_default"} (\texttt{poke\_interval=15s}, \texttt{timeout=300s}, \texttt{mode="poke"}), blocking downstream execution until Bronze files are present.
    \item \textbf{\texttt{prepare\_database}:} Connects via \texttt{PostgresHook(postgres\_conn\_id="postgres\_etl")} and executes idempotent DDL creating \texttt{earthquakes\_curated} and B-tree indexes on \texttt{event\_time} and \texttt{magnitude}.
    \item \textbf{\texttt{find\_and\_load\_bronze\_records}:} Iterates across all JSON files in \texttt{datalake\_bronze/}, flattening nested GeoJSON properties and 3D coordinates while tagging each record with \texttt{source\_file}.
    \item \textbf{\texttt{clean\_and\_normalize}:} Executes the 7-stage Pandas cleansing pipeline (null removal, type coercion, coordinate/magnitude boundary validation, ISO-8601 UTC serialization, text normalization, Gutenberg-Richter energy calculation, and deduplication).
    \item \textbf{\texttt{persist\_to\_silver\_parquet} \& \texttt{persist\_to\_postgres}:} Parallel sink tasks that write Snappy-compressed Parquet files to \texttt{datalake\_silver/} and execute batch \texttt{ON CONFLICT (event\_id) DO UPDATE} upserts into PostgreSQL.
\end{enumerate}

\subsection{Root-Cause Analysis of Run \#2 in Screenshot 3 (Challenges \& Decisions)}
Fig.~\ref{fig:silver_grid} captures the empirical execution history of \texttt{silver\_processing\_dag} during development and testing. While 6 runs succeeded completely (green), \textbf{Run~\#2 (\texttt{manual\_\_2026-11-17T01:33:18+00:00}, second bar from the left) exhibits a red failure square on \texttt{clean\_and\_normalize} and orange (\texttt{upstream\_failed}) squares on \texttt{persist\_to\_silver\_parquet} and \texttt{persist\_to\_postgres}}.

\begin{figure*}[!t]
\centering
\includegraphics[width=0.92\textwidth]{screenshots/03_silver_processing_dag_grid_debugging.png}
\caption{Airflow Grid view for \texttt{silver\_processing\_dag} capturing the diagnostic history: Run~\#2 failed on \texttt{clean\_and\_normalize} due to XCom \texttt{pd.Timestamp} JSON serialization, which was immediately resolved via ISO-8601 intermediate serialization, yielding 6 consecutive green runs thereafter.}
\label{fig:silver_grid}
\end{figure*}

\begin{enumerate}
    \item \textbf{Diagnostic Root Cause:} In the initial version of \texttt{clean\_and\_normalize}, Unix millisecond timestamps were converted directly to Pandas \texttt{Timestamp} objects (\texttt{pd.to\_datetime(df["raw\_time"], unit="ms", utc=True)}) before the task returned \texttt{df.to\_dict(orient="records")}. When a TaskFlow \texttt{@task} returns a Python object, Airflow serializes that return value into the PostgreSQL \texttt{xcom} table using \texttt{airflow.utils.json.XComEncoder}. Because \texttt{pandas.\_libs.tslibs.timestamps.Timestamp} is not natively JSON-serializable, Airflow threw:
    \begin{center}
    \texttt{TypeError: Object of type Timestamp is not JSON serializable}
    \end{center}
    Consequently, \texttt{clean\_and\_normalize} transitioned to \texttt{failed} (red) after exhausting its retry, and Airflow automatically marked the two dependent persistence tasks as \texttt{upstream\_failed} (orange) without executing them.
    \item \textbf{Engineering Fix and Recovery:} We decoupled XCom transport serialization from binary storage typing: inside \texttt{clean\_and\_normalize}, timestamps are formatted as ISO-8601 UTC strings (\texttt{.dt.strftime("\%Y-\%m-\%dT\%H:\%M:\%S.\%fZ")}), which serialize cleanly as standard JSON strings in XCom. Inside \texttt{persist\_to\_silver\_parquet}, the column is re-parsed via \texttt{pd.to\_datetime(df["event\_time"], utc=True)} immediately prior to \texttt{df.to\_parquet()}, preserving native \texttt{datetime64[ns, UTC]} types in the Parquet file. Following this fix, the subsequent 6 runs succeeded in $8\text{--}13\text{ s}$, and clearing Run~\#2 (\texttt{airflow tasks clear}) transitioned the entire DAG history to $100\%$ green.
\end{enumerate}
